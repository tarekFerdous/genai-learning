The RAG order

INDEXING (offline):  load → chunk → embed_documents → store (text + vector)
QUERYING (per req):  embed_query → similarity → top-k → build prompt → LLM → answer

The LLM is the last step. Retrieval is ordinary code that runs before it.

Embeddings

from langchain_ollama import OllamaEmbeddings
emb = OllamaEmbeddings(model="nomic-embed-text")   # 768 dims
vecs = emb.embed_documents(["chunk 1", "chunk 2"])  # list[list[float]]
q    = emb.embed_query("question")                  # list[float]
  • Use the same model for the query and the chunks. Changing models means re-embedding everything.
  • You can't get text back from a vector, so store the chunk text next to it.

Cosine similarity

dot(a, b) / (|a| × |b|)      # 1 = same meaning, ~0 = unrelated

Scores are relative: compare rank and gap, not absolute values. Top-k always returns k items, so a threshold is what lets it return "nothing relevant".

Grounding prompt

Answer using ONLY the context below.
If the answer is not in the context, say "I don't know."

Context:
- {chunk 1}
- {chunk 2}

Debugging a bad answer

  1. Print the retrieved chunks and their scores. Is the right chunk there?
  2. If not, it's a retrieval problem: chunking, embedding model, k, or the query wording.
  3. If it is, it's a generation problem: the prompt, the model, or the context ordering.
