RAG by hand: embeddings, similarity, and the right order

One win: a ~40-line script that does real RAG with no vector DB and no framework magic. You write every step yourself, so you can see what each one does.

Why this next? In Lesson 0001 you put the LLM call before similarity search. Frameworks hide the order inside a single chain.invoke(), so we're building it with no abstractions first. Once you've written retrieve → build prompt → call the model yourself, every vector DB and LangChain retriever is just a faster version of this script.

CheckNo. The model only sees the chunks you put in the prompt. If retrieval misses, the model either says "I don't know" (good) or guesses from its training data (a hallucination). Answer quality can't be better than retrieval quality. You'll prove this yourself in exercise d.

2 · Knowledge: embeddings and similarity

An embedding model turns text into a fixed-length list of numbers (a vector). Texts with similar meaning end up with vectors that point in similar directions, even when they share no words (Boykis, What are embeddings).

Cosine similarity measures the angle between two vectors: 1 means the same direction (same meaning), and values near 0 mean unrelated. Formula: dot(a, b) / (|a| × |b|) (LangChain: Embedding models).

LangChain methodUse
embed_documents(list_of_texts)Indexing: one vector per chunk
embed_query(text)Query time: one vector for the question

A vector database does exactly what you're about to write (store text + vector, return the top-k most similar), plus indexing so it stays fast with millions of vectors. That's all it adds.

3 · Do it

  2. Create labs/rag_by_hand.py. Type it out, and read each comment as you go: 
    import math
from langchain.chat_models import init_chat_model
from langchain.messages import SystemMessage, HumanMessage
from langchain_ollama import OllamaEmbeddings

# ---------- INDEXING (offline, once) ----------
# A fictional company handbook: facts the LLM cannot know from training.
chunks = [
    "Acme Robotics employees may work remotely up to 3 days per week; Tuesday is a mandatory office day.",
    "New hires receive a laptop budget of $2,400, refreshed every 3 years.",
    "Expense reports must be filed within 30 days through the Ledgerly portal.",
    "The on-call rotation is one week long and pays a $500 stipend.",
    "Annual leave is 25 days, plus the office closes between Christmas and New Year.",
    "Production deploys are frozen every Friday after 2pm.",
    "The cafeteria serves free lunch Monday to Thursday.",
    "Security incidents must be reported in #sec-incidents within 1 hour.",
]

embedder = OllamaEmbeddings(model="nomic-embed-text")
vectors = embedder.embed_documents(chunks)
index = list(zip(chunks, vectors))  # our "vector DB": text + vector, side by side


def cosine(a, b):
    dot = sum(x * y for x, y in zip(a, b))
    norms = math.sqrt(sum(x * x for x in a)) * math.sqrt(sum(y * y for y in b))
    return dot / norms


# ---------- QUERYING (per request) ----------
def retrieve(question, k=2):
    q = embedder.embed_query(question)                       # 1. embed question
    scored = [(cosine(q, vec), text) for text, vec in index]  # 2. similarity
    scored.sort(reverse=True)
    return scored[:k]                                         # 3. top-k


question = "Can I deploy to production on Friday afternoon?"
hits = retrieve(question)
for score, text in hits:
    print(f"{score:.3f}  {text}")

context = "\n".join(f"- {text}" for _, text in hits)          # 4. build prompt
model = init_chat_model("qwen3:8b", model_provider="ollama", temperature=0)
response = model.invoke([                                     # 5. THEN call LLM
    SystemMessage(
        "Answer using ONLY the context below. "
        "If the answer is not in the context, say \"I don't know.\"\n\n"
        f"Context:\n{context}"
    ),
    HumanMessage(question),
])
print("\n" + response.content)
  3. Run it with uv run rag_by_hand.py. Look at the numbered comments: steps 1–4 are plain Python, and the LLM only shows up in step 5.

4 · Practice: predict, then run

a. Add print(len(vectors[0])). How many numbers are in one embedding?

Answernomic-embed-text gives 768. Every chunk gets the same length no matter how long the text is, so a long chunk gets squeezed into the same 768 numbers as a short one. Keep that in mind for the chunking lesson.

b. Ask "Is working from home allowed?". Which chunk ranks first, and roughly what score?

What you should seeThe remote-work chunk wins even though it never says "working from home". That's semantic search. Keyword search would have missed it. Note the scores: they're relative, so look at the gap between #1 and #2, not the absolute number.

c. Ask "What is the CEO's name?". What will the model say? What will the top score look like?

What you should see"I don't know." retrieve always returns k chunks, even when none of them are relevant. The top score will be noticeably lower. In production you'd add a minimum-score threshold or let the model refuse.

d. Sabotage retrieval: keep the Friday question, but replace the hits line with hits = retrieve("free lunch").

What you should see"I don't know", even though the right fact is in your index. This proves the warm-up answer: the generator is capped by retrieval. When a RAG system gives a wrong answer, check retrieval first.

e. Remove the "ONLY … I don't know" instruction from the system prompt and repeat c.

What you should seeIt depends on the model. Qwen3-8B usually still says that the CEO isn't mentioned, because modern models are trained to stay with the context they're given. Older, smaller or differently tuned models may invent a name. Keep the instruction anyway: it's one sentence of insurance, and you measure model behaviour (evals, Phase 3) rather than assume it.

f. With the instruction still removed, ask "How many vacation days do Acme interns get?"

Why this one is harderHallucinations usually come from near-misses: the context covers annual leave but never mentions interns. Answering "25" is an unsupported assumption that looks like an answer. Questions that are absent but closely related are the hardest test of how well an answer is grounded, and the most valuable kind to put in an eval set.
"Retrieval quality caps answer quality, because the generator only sees the chunks I give it. So when debugging a bad answer, I check retrieval first, and I evaluate retrieval (context precision and recall) separately from generation (faithfulness)."
