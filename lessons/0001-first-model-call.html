Your first model call, provider-agnostic

One win: a Python script that talks to a local LLM, and that you can point at any provider by changing one string.

Why this first? Every RAG system and every LangGraph agent is built on this one operation: send a list of messages to a model and get a message back. Production systems also need to swap models when a cheaper or better one ships. So we build provider-agnostic from line one.

Indexing (offline): load → split into chunks → embed each chunk → store vectors + text in a vector store.
Querying (per request): embed the question → similarity search → put the top-k chunks into the prompt → LLM generates a grounded answer (ideally with citations).

If you merged the two phases into one line, that's the most common gap. Keeping them apart matters in production: indexing is a batch job, querying is a latency-sensitive API.

2 · Knowledge: what a model call actually is

A chat model is a function: list of messages in → one message out. It keeps no memory between calls. If you want it to "remember", you send the history again (LangChain docs: Models).

PieceWhat it is
SystemMessageInstructions for how the model should behave. In RAG, this is where the retrieved context and the "answer only from the context" rule go.
HumanMessageThe user's turn.
AIMessageThe model's reply. .content is the text, and .usage_metadata holds the token counts (tokens are what you pay for).
init_chat_model(model, model_provider=...)One factory function for every provider. It returns a chat model object with .invoke(), .stream() and .batch().

The video may have used older imports like from langchain.chat_models import ChatOpenAI or LLMChain. Those are pre-v1. We're on LangChain 1.x (v1 migration guide).

3 · Do it

Open PowerShell in D:\gitHub Repos\genai-learning.

  1. Install uv, the standard modern Python project tool (it handles the venv, dependencies and lockfile): 
    winget install --id=astral-sh.uv -e
    Close and reopen PowerShell, then check it with uv --version.
  2. Create the labs project where all our exercises will live: 
    uv init labs
cd labs
uv add langchain langchain-ollama
  3. Pull a local model. Ollama is already installed on your machine. qwen3:8b fits easily in your 16 GB of VRAM: 
    ollama pull qwen3:8b
  4. Write labs/first_call.py. Type it out instead of pasting it, because typing makes you read every line: 
    from langchain.chat_models import init_chat_model
from langchain.messages import SystemMessage, HumanMessage

model = init_chat_model("qwen3:8b", model_provider="ollama", temperature=0)

messages = [
    SystemMessage("You are a concise tutor. Answer in at most two sentences."),
    HumanMessage("What is retrieval-augmented generation?"),
]

response = model.invoke(messages)
print(type(response).__name__)
print(response.content)
print(response.usage_metadata)
  5. Run it: uv run first_call.py

    Qwen3 is a "thinking" model, so you may see a <think>…</think> block or a delay before the answer. That's normal, and we'll control it later.

4 · Practice: predict, then run

For each one, write your prediction in the box first, then change the code and run it. The gap between your prediction and what actually happens is where the learning is.

a. Remove the SystemMessage. What changes?

What you should seeThe answer gets longer and looser, because nothing tells the model to stop at two sentences. The system prompt is your main control lever, and later it's where the RAG context goes.

b. Set temperature=1 and run it 3 times. Then set it back to 0 and run 3 times.

What you should seeAt 1, the wording changes from run to run. At 0, it's (nearly) the same each time. For RAG and evals, you usually want low temperature, because reproducible answers are easier to test.

c. Stream it. Replace the invoke block with:

for chunk in model.stream(messages):
    print(chunk.content, end="", flush=True)
Why it mattersTokens show up as they're generated. Total time is the same, but users see output in a few hundred ms instead of waiting several seconds. Every production chat UI streams, and our capstone API will too.

d. (Optional, needs an API key) Swap providers with one change

uv add langchain-anthropic        # and set $env:ANTHROPIC_API_KEY
model = init_chat_model("claude-haiku-5-5", model_provider="anthropic", temperature=0)

Nothing else in the script changes. That's the point of building provider-agnostic.

"I build against LangChain's provider-agnostic chat interface, so the model is a config value. I develop against a local model for free iteration and deploy on a hosted model for quality and reliability. Switching providers is a config change, not a rewrite."
